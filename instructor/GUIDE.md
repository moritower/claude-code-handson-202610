# 講師用ガイド

このコースを運営する講師向けのメモです。
受講者は「開発初心者」、重点は「要件・設計」と「運用・自動化」。

## 準備（当日まで）

- [ ] 受講者へ事前案内: Node.js 18+ インストール、リポジトリ配布、Claude Code ログイン確認
- [ ] 予備の環境（クラウド端末など）を1〜2台。ローカル環境で詰まる人の避難先
- [ ] `sample-app` で `npm install` → `npm start` → `npm test` が通ることを自分で確認
- [ ] プロジェクタで `docs/*.md` を映せるようにしておく
- [ ] 想定人数に対しアシスタント（TA）を配置できると安心（初心者は環境で詰まりやすい）

## タイムボックス管理

`TIMETABLE.md` の通り。**押したらフェーズ2（実装）を削る**のが基本方針。
重点は 1 と 3 なので、そこは時間を守る。

| パート | 時間 | 死守ポイント |
| --- | --- | --- |
| 準備 | 25分 | 全員 `claude` 起動 & `npm start` 表示まで |
| フェーズ1 ★ | 40分 | SPEC.md / DESIGN.md が各自できる |
| フェーズ2 | 35分 | 動けば十分。完璧を求めない |
| フェーズ3 ★ | 35分 | 最低 CLAUDE.md とコマンドまで |

## パート別・進行のコツ

### 準備（最重要の関門）
- ここでの脱落を防ぐのが成否を分ける。環境エラーは TA が個別対応。
- 全体は待たせず、`docs/00` の基本操作デモを見せて時間を稼ぐ。

### フェーズ1（要件・設計）
- 「AI に答えを出させる」→「AI に問いを出させる」への発想転換を強調。
- SPEC.md ができたら**必ず声に出して読む**よう促す（読まない人が出る）。
- Plan モードは全員で `Shift+Tab` を押して画面表示を確認してから進める。

### フェーズ2（実装）
- diff を承認する前に「どのファイルが変わる?」だけは見る習慣づけ。
- エラーは"隠さず全文貼る"を繰り返しアナウンス。

### フェーズ3（運用・自動化）
- 4つの道具を「速く浅く」全部触れることを優先（深掘りより体験の幅）。
- フック設定は環境差が出やすい。うまくいかない人は「概念の理解」でOKとする。

## よくあるつまずき → 対応

| つまずき | 対応 |
| --- | --- |
| `claude` コマンドが無い | グローバルインストールを再実行。npm の権限エラーなら nvm 経由を案内 |
| ポート3000が使用中 | `PORT=3001 npm start`。前のプロセスを終了 |
| Claude が大きく変更しすぎる | Plan モード / 「小さく分けて」を指導 |
| 仕様が曖昧なまま実装に進む | フェーズ1に戻す。SPEC の受け入れ条件を先に |
| データが消えたと焦る | メモリ保持ゆえ再起動で初期化、と説明（仕様） |
| 返答が英語になる | CLAUDE.md に「日本語で」を入れる好例として活用 |

## 到達目標（この状態なら成功）

- 全員が Claude Code を起動し、対話でファイルを編集できた
- 各自の手元に SPEC.md / DESIGN.md がある
- 予約キャンセルが（多少荒くても）動いた
- CLAUDE.md 追記と自作コマンドを1つ実行できた

## 解答・完成イメージ

- フェーズ2 の完成コードは、講師が事前に別ブランチ/別フォルダで作っておくと
  詰まった受講者にすぐ見せられる（`store.js` の `cancelBooking`、
  `server.js` の `DELETE /api/bookings/:id`）。
- 完璧な解答を配るより、「一緒に直す」プロセス自体を見せる方が学びが大きい。

## クロージングで伝えること

- 今日のコツ3つ（意図を言葉に / 小さく回す / 人が承認する）
- 「明日から、自分の毎回やる作業を1つだけ自動化してみよう」の宿題
- SPEC/DESIGN は持ち帰って読み返す資産になる
