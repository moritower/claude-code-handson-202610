# 仕様: 予約のキャンセル機能

マーダーミステリー公演の予約システムに「予約のキャンセル機能」を追加する。

## 決定事項（前提）

- 公演の**前日まで**はキャンセル可能。公演当日以降はキャンセル不可。
- キャンセル待ちの繰り上げは**今回は作らない**。
- キャンセルすると、その席は**すぐに残席へ戻る**（＝残席計算の対象外になる）。
- 予約レコードは削除せず、`status` を `"cancelled"` に変更して履歴を残す。

## 非対象（今回やらないこと / レビュー反映）

- **部分キャンセル**はしない。`partySize` の一部減席はできず、予約単位で全取り消し。
- **キャンセル待ちの繰り上げ**はしない。
- 最少催行人数（`minPlayers`）を下回っても、残席が戻る以外の処理（通知・催行取消など）はしない。
- 認証・認可は実装しない（下記「前提・制約」を参照）。
- 画面（`public/`）のキャンセルUIは本仕様の対象外（API のみ）。実装時は一覧の再取得が必要になる点を別途フォローする。

## 前提・制約（レビュー反映）

- **認可なし**: 予約IDは `b1, b2, …`（連番）で推測可能なため、IDを知る／総当たりすれば他人の予約もキャンセルできる。学習用アプリとして**この制約を許容**し、本番では本人確認が必要なことを明記する。
- **永続化なし**: データはメモリ上（`src/store.js`）。サーバー再起動でキャンセル結果も失われる。
- **デモデータの注意**: `seed()` の公演には今日より過去の日付が含まれる場合がある。過去公演の予約は本仕様上キャンセル不可になるため、動作確認は**未来日付の公演**で行うこと。

## 1. ユーザーストーリー

> **予約者**として、
> 都合が悪くなったときに**予約済みの公演をキャンセル**したい。
> なぜなら、行けなくなった席を**他の人が予約できるよう**にしたいから。

補足:

- 予約者は自分の予約IDを使ってキャンセルを行う。
- 公演の前日まではキャンセルでき、キャンセルした分の席はすぐ空席として他の人に開放される。

## 2. 受け入れ条件（テストできる粒度）

### キャンセルの成功

- [ ] `status` が `"confirmed"` の予約をキャンセルすると、その予約の `status` が `"cancelled"` に変わる。
- [ ] キャンセル後、その公演の残席数（`remainingSeats`）がキャンセルした人数（`partySize`）ぶん増える。
- [ ] 満席だった公演でキャンセルが発生すると、`isSoldOut` が `false` に戻る（空席が出る）。
- [ ] キャンセルされた予約は、残席・満席の計算対象から外れる（`status === "confirmed"` のみを数える既存ルールに従う）。
- [ ] 「`confirmed` の確認 → `cancelled` への更新」は**1つの同期処理内で完結**させ、途中に `await` を挟まない（二重取り消しで席が二重に戻るのを防ぐ）。

### 存在しない予約ID

- [ ] 存在しない予約IDを指定した場合はキャンセルできず、`404` と「予約が見つかりません」を返す。
- [ ] 存在しない予約IDを指定しても、既存の予約の `status` や各公演の残席数は一切変化しない（副作用なし）。

### キャンセルできない / エラー

- [ ] 公演**当日以降**（公演日時の前日を過ぎた）予約はキャンセルできず、「公演前日までにキャンセルしてください」として扱う。
- [ ] 公演**前日まで**（前日およびそれ以前）の予約はキャンセルできる。
- [ ] すでに `"cancelled"` の予約を再度キャンセルしようとした場合は、「すでにキャンセル済みです」として扱う（席は二重に戻さない）。
- [ ] 複数の失敗条件が同時に成立する場合、**判定順は「①存在確認(404) → ②キャンセル済み(400) → ③期限切れ(400)」**とし、最初に該当したエラーを返す。

### 影響範囲

- [ ] キャンセルで最少催行人数（`minPlayers`）を下回っても、残席が戻る以外の特別な処理は行わない（繰り上げ・通知なし）。
- [ ] キャンセル処理はキャンセル待ちの繰り上げを行わない。

### 判定の基準日（レビュー反映）

- [ ] タイムゾーンは **Asia/Tokyo（JST）固定**で判定する。`performance.datetime`（例 `"2026-10-18T18:30"`）はJSTのローカル時刻とみなす。
- [ ] 「前日まで」は**日付基準**。公演日の前日 23:59:59（JST）までキャンセル可、公演日の 00:00:00（JST）以降は不可。
  - 例: 公演が `2026-10-18T18:30` なら、`2026-10-17` 中はキャンセル可、`2026-10-18` 00:00 以降は（公演開始前の朝でも）不可。
- [ ] 日時の比較は**文字列の辞書順ではなく `Date` オブジェクト（または年月日の数値）で**行う。
- [ ] 期限判定の純粋関数は現在時刻を引数で受け取る（例 `canCancel(performance, booking, now)`）。テストで任意の `now` を注入できること。`server.js` 側だけが `new Date()` を渡す。

## 3. API の入出力

### エンドポイント

```
DELETE /api/bookings/:id
```

- `:id` … キャンセル対象の予約ID（例: `b1`, `b_demo`）

### リクエスト

- パスパラメータ `id` のみ。リクエストボディは不要。

```
DELETE /api/bookings/b1
```

### レスポンス

#### 成功: `200 OK`

キャンセル後の予約オブジェクトを返す。

```json
{
  "id": "b1",
  "performanceId": "p1",
  "name": "サンプル太郎",
  "partySize": 2,
  "status": "cancelled",
  "createdAt": "2026-10-15T10:00:00.000Z"
}
```

#### 失敗: `404 Not Found`

指定した予約IDが存在しない。

```json
{ "error": "予約が見つかりません" }
```

#### 失敗: `400 Bad Request`

キャンセルできない状態（公演当日以降、またはすでにキャンセル済み）。

```json
{ "error": "公演前日までにキャンセルしてください" }
```

```json
{ "error": "すでにキャンセル済みです" }
```

### 備考

- 残席・満席の再計算は既存の `GET /api/performances` が `status === "confirmed"` のみを数えるため、キャンセル（`status = "cancelled"`）で自動的に席が戻る。
- ドメインのキャンセル可否判定は純粋関数として `src/booking.js` に置く想定（例: `canCancel(performance, booking, now)`）。実際の `status` 更新は `src/store.js` 側に置く想定。
