# 03. フェーズ2: 実装（1:40–2:15 / 35分）

フェーズ1 で作った **SPEC.md / DESIGN.md をもとに**、実際に動かします。
「仕様が実装のガイドになる」感覚を体験しましょう。

---

## Step 1. 設計どおりに実装させる（12分）

Plan モードを解除（通常モードに戻す）してから:

```
docs/DESIGN.md の計画どおりに、予約キャンセル機能を実装して。
- src/store.js に cancelBooking(id) を追加
- server.js に DELETE /api/bookings/:id を追加
- SPEC.md の受け入れ条件を満たすこと
変更後に npm test を実行して結果を教えて。
```

Claude Code が変更を提案してきたら、**diff（変更点）を読んで**から承認します。

> 🔑 全部を理解できなくてOK。でも「どのファイルが変わるか」だけは見る習慣を。

---

## Step 2. 動かして確かめる（8分）

```bash
npm start
```

ブラウザで <http://localhost:3000> を開き、予約 → その予約を消す、を試します。

画面にキャンセル用の導線が無ければ、追加を頼みます。

```
管理しやすいように、予約一覧（GET /api/bookings）を見られる簡単な画面と、
各予約にキャンセルボタンを付けて。凝らなくていい。
```

---

## Step 3. うまくいかない時（デバッグ）（10分）

エラーが出たら、**そのままコピペ**して渡すのが一番早いです。

```
npm start したらこのエラーが出た。原因と直し方を教えて:
（ここにエラーメッセージを貼る）
```

Claude Code は原因の仮説 → 修正案を出します。
直してもらったら、もう一度動かして確認します。

> 💡 「エラー文は宝の地図」。隠さず全部渡すほど、早く直ります。

---

## Step 4. 仕様との答え合わせ（5分）

```
今の実装は SPEC.md の受け入れ条件を全部満たしている?
満たしていない項目があれば表にして。
```

満たせていない項目があれば、1つずつ直します。
これで「仕様 → 実装 → 検証」の一周が完成です。
