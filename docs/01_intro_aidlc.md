# 01. AIDLC とは（0:10–0:20 / 10分）

## AIDLC = AI 駆動開発ライフサイクル

ソフトウェア開発には、昔から次のような流れ（ライフサイクル）があります。

```
要件  →  設計  →  実装  →  テスト  →  運用
（何を作る?） （どう作る?） （作る）  （確かめる）  （使い続ける）
```

**AIDLC** は、この各段階で AI（Claude Code）を"相棒"として使う進め方です。
大事なのは、**AI に丸投げしない**こと。役割を分けます。

> 📝 **補足**: 「AIDLC」に業界共通の唯一の定義はありません。ここでは
> 「開発の各段階で AI を使い、人が判断・承認する」という**広い意味**で扱います。
> AWS などが提唱する具体的な方法論との関係は、この章の最後で触れます。

| 段階 | 人がやること（判断・意図） | AI に任せられること（具体化・反復） |
| --- | --- | --- |
| 要件 | 何を実現したいか決める | 要望の整理・抜け漏れの指摘・仕様書化 |
| 設計 | 方針を選ぶ | 選択肢の提示・設計メモの作成 |
| 実装 | ゴールと制約を伝える | コードの生成・修正 |
| テスト | 何を守りたいか決める | テストの作成・実行 |
| 運用 | ルールを決める | 反復作業の自動化・定型処理 |

## このコースでの重点

今日は特に、両端の 2 つをじっくり体験します。

- **フェーズ1: 要件・設計** ★
  「マーダーミステリーの予約システムに、こんな機能が欲しい」という
  ふわっとした要望を、Claude Code と対話しながら
  **仕様書と設計メモ**という“読める形”にします。

- **フェーズ3: 運用・自動化** ★
  テストや整形といった**毎回やる面倒な作業**を、
  コマンド一発／自動実行で回せるようにします。

（間の**フェーズ2: 実装**は、両者をつなぐ体験として軽く行います）

## 今日ずっと意識してほしい 3 つのコツ

1. **意図を言葉にする** — 「なぜ・何を・どこまで」を伝えるほど良い結果になる
2. **小さく回す** — 一度に大きく作らず、確認しながら少しずつ
3. **人が承認する** — AI の提案は"下書き"。読んで判断するのは自分

> 🧭 迷ったら「自分は何を実現したいんだっけ?」に立ち返る。
> それが AIDLC で一番大切なスキルです。

## 補足: 「AIDLC」には色々な定義がある（30秒）

AIDLC に単一の標準定義はありません。AWS などが提唱する**具体的な方法論**
（例: AWS の「AI-DLC」）もその一つですが、本コースは初心者向けに
「まず体験する」ことを優先し、一番**広い意味**の AIDLC で進めます。

> もっと本格的にやりたくなったら、AWS のオープンソース実装フレームワークが
> あります（付録の「もっと学ぶには」を参照）。
