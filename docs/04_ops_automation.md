# 04. フェーズ3: 運用・自動化 ★重点（2:20–2:55 / 35分）

このパートのゴール:

> テストや整形などの**毎回やる面倒な作業**を、
> Claude Code に"仕組み"として覚えさせ、自動で回せるようにする。

4 つの道具を順に体験します。
**CLAUDE.md → スラッシュコマンド → フック → サブエージェント**。

---

## Step 1. CLAUDE.md にルールを育てる（8分）

`sample-app/CLAUDE.md` は Claude Code が**毎回自動で読む**指示書です。
ここにチームの約束を書くと、毎回説明しなくて済みます。

Claude Code に頼んで追記します。

```
CLAUDE.md に、このプロジェクトの約束として次を追記して:
- 変更したら必ず npm test を実行する
- ドメインのルールは src/booking.js に純粋関数で書く
- package.json の scripts は勝手に消さない
- 返答とコメントは日本語
```

追記後、試しに新しい会話（`/clear`）を始めて、
「このプロジェクトのルールは?」と聞くと、ちゃんと覚えています。

> 🔑 CLAUDE.md は"チームの共通ルールブック"。
> 人が変わっても AI の振る舞いが揃います。

---

## Step 2. スラッシュコマンドを作る（9分）

よく使う指示は、`/コマンド` として登録できます。
`.claude/commands/` に Markdown を置くだけです。

例として「変更をレビューするコマンド」を作ってもらいましょう。

```
.claude/commands/review.md を作って。
内容は「今の変更点(diff)を読み、SPEC.md の受け入れ条件に照らして
問題がないかレビューし、指摘を重要度つきで箇条書きにする」指示にして。
```

できたら、Claude Code で次を実行:

```
/review
```

同じ要領で、`/add-test`（不足しているテストを追加する）なども作れます。

> 💡 「毎回打っている長い指示」を見つけたら、それはコマンド化のサイン。

---

## Step 3. フック（hooks）で自動実行する（10分）

**フック**は「○○したら自動で△△する」という仕掛けです。
Claude が判断するのではなく、**ツール（ハーネス）が確実に実行**します。

今回は「**ファイルを編集したら自動でテストを走らせる**」を設定します。
Claude Code に、設定変更を頼みましょう（設定ファイルを安全に編集してくれます）。

```
ファイルを編集・作成したあとに自動で `npm test` を実行するフックを、
このプロジェクトの設定に追加して。失敗したら結果が分かるようにして。
```

設定されると、以降は編集のたびにテストが自動で走ります。

参考: `settings.json` に入るイメージ（手で書く必要はありません）

```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          { "type": "command", "command": "npm test --silent" }
        ]
      }
    ]
  }
}
```

> 🔑 フックの価値は「**忘れない・サボらない**」こと。
> 品質チェックを人の記憶に頼らず、仕組みで守れます。

---

## Step 4. サブエージェントに調査を任せる（6分）

大きな調べ物は、**サブエージェント**という"別働隊"に任せられます。
本体の会話を汚さずに、並行で作業させるイメージです。

```
このプロジェクト全体を調べて、
「入力バリデーションが甘い箇所」を洗い出すサブエージェントを立てて。
結果は箇条書きで要約して。
```

Claude Code が調査役を起動し、結果だけを持ち帰ってくれます。
大きなリファクタや調査のとき、本体を軽く保てます。
