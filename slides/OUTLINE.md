# スライド構成案（プレゼン用）

各スライドは「1枚 = 1メッセージ」を意識。合計 約28枚。
講義パートは短く、手を動かす時間を最大化する。

---

## 導入（オープニング / 概論）

1. **タイトル** — Claude Code で学ぶ AIDLC ハンズオン（3時間）
2. **今日のゴール** — 3つ（全体像 / 要件・設計 / 運用・自動化）
3. **対象と前提** — 初心者向け / ターミナルが打てればOK
4. **今日の題材** — マーダーミステリー公演 予約システム（画面スクショ）
5. **進め方** — 講義は短く、手を動かす。休憩4回。
6. **AIDLC とは** — 要件→設計→実装→テスト→運用の図
7. **人と AI の役割分担** — 「人は意図、AI は具体化と反復」の表
8. **今日の重点** — 要件・設計 ★ と 運用・自動化 ★（両端を厚く）
9. **3つのコツ** — 意図を言葉に / 小さく回す / 人が承認する

## 準備パート

10. **環境チェック** — node -v / claude
11. **Claude Code を起動** — サンプルアプリを開く
12. **基本操作デモ** — 読ませる・聞く・小さく直す（ライブデモ推奨）
13. **便利キー** — Esc / Shift+Tab / ! / /clear

## フェーズ1: 要件・設計 ★

14. **章扉** — 「作る前に、言葉にする」
15. **やること** — ふわっとした要望 → SPEC.md / DESIGN.md
16. **コツ: 問いを出させる** — 「質問を5つ挙げて」
17. **仕様書の3点セット** — ユーザーストーリー / 受け入れ条件 / API
18. **Plan モード** — 「作る前に計画を見る」図解
19. **ハンズオン開始（40分）** — 手順は docs/02 を投影

## フェーズ2: 実装

20. **章扉** — 「仕様が実装のガイドになる」
21. **流れ** — 設計どおり実装 → 動かす → デバッグ → 答え合わせ
22. **デバッグのコツ** — エラー全文を貼る
23. **ハンズオン開始（35分）** — 手順は docs/03 を投影

## フェーズ3: 運用・自動化 ★

24. **章扉** — 「面倒は仕組みに任せる」
25. **4つの道具** — CLAUDE.md / コマンド / フック / サブエージェント（1枚図）
26. **フックの価値** — 「忘れない・サボらない」
27. **ハンズオン開始（35分）** — 手順は docs/04 を投影

## クロージング

28. **振り返り & 持ち帰り** — 3つのコツ再掲 / 身近な作業を1つ自動化してみよう / Q&A

---

## 作成メモ

- 各「ハンズオン開始」スライドでは、対応する `docs/*.md` を画面共有し、
  受講者は手元で同じファイルを開いて進める。
- ライブデモ（12番）を1回入れると、初心者の不安が大きく減る。
- 図が要るスライド: 6（ライフサイクル）, 7（役割分担）, 18（Plan）, 25（4つの道具）。
